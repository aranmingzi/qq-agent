## 1. P0 —— 判据级缺口，小改动大收益

### 1.1 淡化 ≠ 删除（判据 3 / R4 / 蒸馏版陷阱二）⭐ 最重要的一条

现状：`decayFacts()` 按天降权重 → `forgetWeakFacts({ minWeight })` 把低于线的**物理删除**
（rule/negative 除外）。原始消息在归档里保住了，但**事实层**的"淡忘"是真的没了。

四份文档在这个点完全一致：
- 对外版：「日常所谓淡忘 → 召回权重降到注入线以下；原文/事件卡永久保留；物理删除只有用户明确说忘掉」
- 方案 R4：「自然淡化…保留来源与可核查的事件骨架」「显式遗忘…留下墓碑阻止旧数据重新学习」
- 蒸馏版陷阱二：「曲线调的是召回权重，不是删除速度。用错语义，后面所有参数都会拧」

**改法**：`forgetWeakFacts` 改成打 `dormant: true`（休眠位），召回端跳过休眠项；
物理删除只留给显式的用户遗忘指令；显式遗忘要写墓碑（内容摘要 + 时间 + 原因），
检索时优先排除，防止旧事实被下一轮提取"重新学到"（反思链会重读归档，没有墓碑就会复活）。

### 1.2 玩笑/碎句不入事实（判据 1 边界①）

现状：反思提取的输入是「该人最近 N 句」，`嗯/哦/哈` 这类弱句会跟着进提示词；
提示词没有一条「玩笑、反讽不提取」的禁令。对照实测教训（「我明天就把你卖了」进承诺、
「嗯嗯」被记成「她说好」），这是编造事实的主要入口。

**改法**：
- `buildExtractionPrompt()` 加两条硬规则：玩笑/反讽一律不提取（宁可不进，不可误当事实）；
  弱句（去表情后为空、单字、纯标点、复读）不计入语料。
- 判据 1 的强中弱三档可以直接抄进 `past-summary` 的入料过滤（中/强才值得压进摘要）。

### 1.3 事实没有原话引用（对外版纪律 2「没有原话的记录，隔天就要怀疑它」）

现状：`rememberFact` 只存 `source`（chatKey，24 字符），**不存消息 id**。
要核对「她原话怎么说的」只能靠人去翻归档，模型没有任何通路从事实跳回原文。

**改法**：fact 加 `mid`（QQ 消息 id）或 `quote`（原句摘录 ≤60 字）。
召回注入时带一句「出处：archive/<chat>/<日期>.jsonl #<mid>」，回答细节前有据可查（R5 尾巴）。

### 1.4 推翻 = 新增一条，旧的标掉（对外版纪律 4 / xiaoyu 失效层）

现状：重复提及是原地强化（+0.3），`kind` 只升不降，`rememberRelation` 干脆覆盖式。
**没有"更正"通路**：模型这次提出来一个和旧事实冲突的说法，要么撞 `normalizeKey` 去重（不同文本撞不上），
要么并存两条互相矛盾的事实，注入时模型挑顺口的信 —— 正是对外版说的「冲突不保存、静默选顺口的一版」（R6）。

**改法**：`rememberFact` 检测同主体低编辑距离/同宾语冲突时，新条目带 `supersedes: <oldId>`，
旧条目打 `supersededAt`（不删，保留"它当年真过"）；召回端旧条目不再注入。
xiaoyu 的「双时态」（从哪天起不成立 / 哪天标掉的）值得照抄成两个字段。

## 2. P1 —— 结构级缺口（方案 R1/R2/R3 的主菜）

### 2.1 没有事件层

现状：粒度只有三层 —— 原始消息（store）、条目式滚动摘要（past-summary，8 条 × 800 字）、
事实/日记。**"一段经历"（起因→经过→转折→结果）没有任何载体**：
摘要按时间滚动，关键更正可能被后续批次稀释；事实是原子断言，没有过程。

方案 R1 的事件判据可以低成本落在现有归档上（不必建新表，一个 JSON 每天一份即可）：

```
边界：① 主题对象变了 ② 间隔 ≥30 分钟 ③ 显式换话题词（"对了/不说这个了"）
事件卡：{ 参与者, 场景, 时间, 起因, 关键过程, 结果, 状态(open/done), 来源 mid 列表 }
open 的事件后来出结果 → 新版本，不提前编结局
```

判据 2 反例直接当测试用例：聊 300 字全是玩笑、主题没变 → 不拆；「对了，明天体检」→ 拆。

### 2.2 承诺/未完成事项没有单独治理（R3）

现状：`pendingThought`（想说没说的话）默认 **2 小时过期**。承诺、约定混在普通事实里，
按 `decayFacts` 0.02/天衰减 —— 两个月后「答应周四交报告」权重掉到注入线以下，
然后被 `forgetWeakFacts` 删掉（1.1 的语义拧在这里叠加放大）。

**改法**：kind 加 `commitment`（或沿用 rule 的保护路径）：完成/取消前不衰减、不参与丢弃、
必入召回名额（与 rule/negative 同待遇）；提取提示词里把「答应/说好/还没」列为必提取项。
判据 1 的「强」档定义里"含承诺与未完成"就是给它用的。

### 2.3 一次观察不算数（对外版纪律 1）

现状：提取出一条事实就以 weight=1 落库并参与注入。单次模型输出可能是误读、玩笑或反讽（1.2 的漏网）。

**改法**：新事实先落 `candidate` 态（不注入、不占 60 条名额），**另一次独立会话**再次出现
（重复提及、新结果、用户明确标记）才转正。防串人纪律已经保证"按人分组"，
所以"独立出现"的判据可以用「不同时间批次的提取」。

## 3. P2 —— 运维与治理

### 3.1 备份（蒸馏版已知断线 #2 在我们这里的同款）

现状：`memory.js` 给自己的 JSON 留 3 份轮转；**facts、messages、archive、diary、summary 都没有备份**，
全在 `DATA_DIR`（应用私有目录）—— 卸载/换盘全没。蒸馏版原话：「卸载应用/换机撑得住；手机丢了全没」。

**改法**：学 `backup.mjs` 做一个每日 `data/` → 异地/共享目录镜像（按天分片、保留 N 份、写 manifest）。
facts 和 archive 优先，几 MB 的事。

### 3.2 摘要来源依赖与失效传播（R7 尾巴）

现状：past-summary 的条目不声明"由哪些消息压出来的"；更正/遗忘一条事实时，
旧摘要不会跟着失效。当前规模可以先不做反向索引，但事件卡落地时（2.1）
**来源 mid 列表必须从第一天就是字段**，否则以后补不起来。

### 3.3 五组验收（对外版「怎么验证」）

五组铺垫→提问→对照（周四改周五 / 谁咬谁 / 卖你玩笑 / 称呼更正 / 私聊边界）
可以直接写成离线测试的断言数据集（`test/test-memory-criteria.mjs`），
每组标明"不合格"长什么样。当前测试覆盖的是机制（去重/权限/衰减），
**没有任何一条测"语义对不对"** —— 而对外版的核心警告正是「顺比错难查」。

### 3.4 描述层索引（xiaoyu 检索层）

xiaoyu 的「每份文件一行：它是什么 + 什么时候翻」对我们等于给模型一张**记忆库地图**：
现在 prompt 里注入的是条目本身，模型不知道"还有什么可查"（有哪些日记、哪个人有事实档案）。
低成本版：注入段加一行库存摘要（`facts: 3 人共 27 条 · diary: 12 天 · 摘要覆盖至 msg#8123`）。

## 5. 一句话总结

**该抄的判据是四份文档重叠最厚的三件事：淡化≠删除、玩笑不入事实、更正=新增+旧条标掉。**
我们的三层结构（原文/条目/事实）和召回算法（概率+联想）不落后，落后的是**失效语义**：
现在只有"删除"和"保留"两态，缺"休眠、作废、候选"三态；而且失效不传播。
先把失效语义改对，事件层才有地方挂。
