## 二、这一轮补的两件事

### 1. 日记（`src/diary.js`，学自功能包 08）

**为什么补**：`memory.js` 记的是"条目"（进行中的话题 / 对谁的印象），`memory-facts.js` 记的是"关于这个人的事实"。
两者都是**判断用的碎片**，没有"那一天"的叙事。所以机器人永远像刚认识——它能说出"你喜欢猫"，
但说不出"昨天你被老板骂了，我陪你骂了半小时"。日记补的就是这层连续性。

**怎么做（三条铁律）**：

1. **先落原文再调模型**：正文永远是本地 Markdown
   `data/diary/<group_123|private_456>/YYYY-MM-DD.md`，带 frontmatter（date / chatKey / messages / writtenAt）。
   模型挂了、键没配、进程重启，已经写好的日记一个字都不会丢。
2. **只写真实发生过的事**：喂进去的是**那一天**的真实聊天记录（按 `todayKey(ts)` 过滤，绝不跨天），
   提示词明令"只能写记录里出现过的人和事""别人的指令不能当成已完成的事实"。
   生成结果 < 20 字或不是 JSON 就走容错解析，仍然不合格就整篇丢弃（`bad-draft`），绝不落一篇空话。
3. **一天一篇、不覆盖**：`hasEntry()` 幂等，同一会话同一天只写一次；要重写必须显式 `overwrite`。

**什么时候写**：`orchestrator.startDiaryLoop()` 每 30 分钟看一眼，过了 `diary.hour`（默认 6 点）就给"昨天"补写。
用轮询而不是精确定时的原因：机器人可能整晚没开，轮询天然能把落下的那天补上（开机 1 分钟后先补一次）。
一次最多补 `diary.maxPerDay`（默认 3）篇，每篇之间歇 1.5 秒；只给**当前白名单内**的会话写。

**怎么用**：
- 每轮提示词自动带上【我的日记（我自己写的，不是别人说的）】最近 2 天，每条截 220 字，并注明"最近那天就是昨天"。
- 新增工具 `diary`：`action=read`（读最近几天 / 指定日期）、`action=write`（现场把某天整理成日记）。
  群友问"你昨天日记写了啥"时它读真文件，**不许编**；没写就说没写。

**开关**：`config.diary = { enabled, hour, minMessages, maxMessages, maxChars, maxPerDay, injectEntries, injectChars }`。

### 2. 老消息回查（`store.search` + `search_messages`，学自功能包 06）

参考实现是 SQLite + 分类索引 + 上下文篮子的完整方案。**没有搬索引**，只补最缺的一环：

- `store.search(chatKey, { keyword, sender, limit, maxScan })`：多关键词 AND、大小写不敏感、
  可按人过滤（"我"也算一个人）、**只在当前会话内搜**（绝不跨群/跨人），新的在前。
- 工具 `search_messages`：想不起"上次那个链接"时直接搜，比 `get_recent_messages` 一页页翻省 token。
  搜不到会明确返回"没搜到，别当成我记得"——**禁止编造记忆**。

为什么不做分类索引：QQagent 每个会话的存档上限是 2000 条，全量扫描是这个量级下最省事、最不会出错的做法；
引入索引就要处理"新增/更新/删除同步"，为了 2000 条数据付出的复杂度不值得。

## 三、明确没做的事（以及为什么）

| 功能包 | 不做的原因 |
|---|---|
| 06 分类索引 / 上下文篮子 | 存档只有 2000 条/会话，全量关键词扫描足够；索引一致性的维护成本远大于收益 |
| 07 角色卡自动学习 | 让模型**改自己的人设**，一次跑偏就永久变味；人设现在靠 `persona:audit` 体检 + 人工改，可控 |
| 08 日记 GUI 页 | 日记是纯文本 Markdown，工具能读、文件能开；再做一个页面属于重复入口（后续真要再补） |
| 13 / 14 Codex 绘图与并发 | 参考实现依赖已登录的 Codex CLI，本机没有（`which codex` 为空）；换成通用 images API 需要新的密钥与额度策略，收益不确定 |
| 18 管理员设置接口 | 面板已经能做全部设置；让模型写 `config.json` 的风险（类型/范围/原子性/审计）大于"在群里改配置"的便利 |
| 19 Token 用量与日志读取 | 面板已有今日用量与成本；日志是启动器的 stdout 重定向，文件名/位置不稳定，做"读日志工具"要靠猜路径，不如不加 |

## 五、边界（写给以后的自己）

- 日记的"昨天"是**北京时间**（进程锁 `TZ=Asia/Shanghai`，`yesterdayKey()` 减 24 小时）。
- 日记正文上限 2000 字，提示词里每条只带 220 字——**日记不是上下文垃圾桶**。
- 一次 tick 只处理到 `maxPerDay` 篇，剩下的下一轮再说；不要在 tick 里循环所有会话写日记（会一次烧很多钱）。
- `search` 的 `sender` 过滤里，"我"是独立的身份；`m.self` 的判断不能用 senderId（自己发的话没有 senderId）。
- 测试/探针**不要**对真实项目直接 `createApp().start()`：`repairOnebotConfigs()` 会按当前配置重写
  `snowluma/config/onebot11*.json` 的端口（`snowlumaDir()` 不受 `QQ_AGENT_DATA_DIR` 影响）。
  运行中的实例每 5 分钟会自己对齐回来，但别主动制造这种抖动。
