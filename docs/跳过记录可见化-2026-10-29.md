## 1. 原来错在哪

`/api/skips` 在 `src/app.js:1856` 就有，返回 `{items, stats}`。
`SKIP_STAGES` 从第 1 轮起就在记账，二十个阶段一个不少。

但把它翻遍整个前端：

```
ui/app.js            → 出现 "skips" 的次数：0
ui/index.html        → 四个 tab：sessions / chats / snowluma / settings
console/src/lib/api.ts          → 有 gateDecisions()，没有 skips()
console/src/features/health/health-page.tsx → 只有 skipped: '判据判为不接'
```

也就是说：**记账是完整的，读账的地方不存在。**

这不是"少个功能"，而是把前几轮的价值全埋了：

- 第 1 轮「失败可见化」：模型挂了会说一句人话 —— 但"为什么这一轮整个没跑"看不见。
- 第 3 轮「发送额度前置感知」：额度满就跳过、省下模型钱 —— 省了多少，面板上是 0。
- 第 4 轮「主动消息退避」：连续没人接就安静 —— 安静得连"我在退避"都看不出来。

四份变更说明里，有三份把这件事写进了「残留问题」（`失败可见化` 2 处、
`主动消息收敛` 4 处、`发送额度前置感知` 3 处、`能力前置可见化` 2 处）。
**同一个缺口在四轮里被记了十一次，却一直没修** —— 因为它不属于任何一轮的"主线"。

这次它是主线。

## 2. 借鉴了什么

### 2.1 AstrBot：stage 是给人看的，不是给日志看的

AstrBot 4.29.3 的 pipeline 用 `Stage` 基类 + `stage_name`，每个阶段有
中文 `display_name`，面板直接按它渲染。对照我们：`SKIP_STAGES` 的值是
`send-quota` / `proactive-backoff` 这种**机器串**，直接甩给用户等于没翻译。

借鉴的是**分层**而不是代码：枚举保持机器串（程序判断用），
展示层单独一层标签表（人看）。两层之间的映射必须唯一 —— 见 §3.1。

### 2.2 MaiBot：运营故障不外泄，但要能自证

MaiBot 的日志分"给运营看的"和"给用户看的"两套。它不会把
"频率限制"这种内部状态塞进群聊，但运营后台一定能查到。

对应到我们这里就是 `spent` 这个字段：面板要能一眼分出

- **没花模型钱**的跳过（额度满、退避中、判据不接）→ 这是省钱，不是故障；
- **花了钱却没开口**的（判据自身出错、出口拦截、整轮报错）→ 这才值得看一眼。

以前 `stats` 只给次数，用户看到"今天 42 次没回"根本判断不了要不要管。

### 2.3 没有借鉴的部分

- AstrBot 的 `display_name` 是阶段自己声明的（`stage_name` 属性）。
  我们没这么做：`SKIP_STAGES` 是纯字符串枚举，挂在 `skip-log.js` 里，
  而 `skip-log.js` 已经 211 行且被 `orchestrator/sender/app` 三处依赖。
  把中文塞进枚举会让"记账"和"展示"重新耦合。**独立成 `skip-labels.js`。**

## 3. 改了什么

### 3.1 `src/skip-labels.js`（新增，约 240 行）

二十个 stage 的中文标签表，**唯一实现**。三个字段分工：

| 字段 | 用途 | 例子 |
| --- | --- | --- |
| `label` | 表格/徽章里的短标签 | `额度已满` |
| `hint` | 一句话说清这意味着什么 | `这一分钟/小时的发言额度用完了，开跑前就放弃，**没花模型钱**。` |
| `action` | 该怎么办；空串 = 正常现象不用管 | `经常撞说明额度设太低，或模型话太密。` |

外加 `spent`（这一轮有没有花模型钱）。

导出：

- `describeStage(stage)` → 返回**副本**；未知 stage 退回原文 + `未知阶段（可能是旧版本或插件写的）`。
  为什么不返回空白：面板上一格空白比写"未知"更让人困惑。
- `stageLabel(stage)` → 短标签，日志行用。
- `stageTable()` → 数组（不是对象，跨端不该依赖 key 顺序）。
- `explainStats(stats)` → 翻译 + 过滤 0 + 排序（次数降序，同次数按枚举顺序）。
- `summarizeStats(stats)` → `共 42 次没开口，其中 31 次没花模型钱`。

**排序为什么必须在这里做**：次数降序 + 同次数按枚举顺序，这条规则每个消费方
都会各写一遍，而最容易写歪的就是"同次数怎么办" —— 写歪了面板刷新一次跳一次。

### 3.2 `src/app.js`：接口把标签一起吐出来

`/api/skips` 从返回 `{items, stats}` 变成：

```js
{
  items:   [...],  // 每条带 label / hint / action / spent
  stats:   {...},  // 原样保留（兼容老调用方）
  rows:    [...],  // explainStats(stats)：翻译 + 排好序
  summary: '共 N 次没开口，其中 M 次没花模型钱',
  stages:  [...]   // stageTable()：面板图例/筛选器用
}
```

**为什么翻译放服务端**：前端再写一份 map 必然漂移（第 4 轮的
`#minuteLimit` 就是靠"抽成唯一实现"才止住漂移的，见
`docs/发送额度前置感知-2026-10-29.md` §3.4）。而且 `stages` 直接跟着枚举走，
加一个 stage 前端自动就有。

### 3.3 控制台：运行体检页新增第 5 块

`console/src/lib/api.ts` 新增 `SkipRecord` / `SkipStatRow` / `SkipBundle`
类型 + `normalizeSkips()` + `api.skips(limit, sinceMs)`。
`normalizeSkips` 里 `label: asString(item.label) || stage` —— 万一连到旧版本
后端（只回 `{items, stats}`），退回 stage 原文而不是显示空白。

`health-page.tsx` 新增「刚才为什么没开口」区块：

- 顶部一句话解释"没花钱的不用管，花了钱的才值得看"；
- 统计徽章行（前 8 类，`spent` 决定徽章颜色：warning / neutral）；
- 明细列表：标签 + 「没花模型钱」+ chatKey + 相对时间 + 原因 + hint + action + detail + traceId；
- **默认只看花了钱的**（`onlySpent` 默认 `true`），底部提示"另有 N 次没花模型钱，已折叠"。
  理由：没花钱的跳过是正常运转，默认全展开会把真正要看的那几条淹掉。

`api.skips()` 也进了 `Promise.allSettled` 的第六路 —— 任何一路失败只降级自己，
不会整页白屏（沿用这一页原有的写法）。

### 3.4 前端产物已重新构建

`cd console && npm run build:electron` → `ui-console/assets/index-DKgyB5Yk.js`。
验证：`grep -c "刚才为什么没开口"` = 1，`grep "api/skips"` 命中。

> 注意：这一步是**必须**的。`src/app.js:3258` 在 `ui-console/index.html` 存在时

## 4. 踩到的坑

### 4.1 `echo $?` 拿到的是 `tail` 的退出码

第一次做变异验证时写成：

```bash
node test/test-skip-labels.mjs 2>&1 | tail -35; echo "EXIT=$?"
```

`$?` 是管道最后一个命令（`tail`）的退出码，**永远是 0**。
于是"测试 18 通过 / 1 失败"却显示 `EXIT=0` —— 差点得出"变异没被抓到"的错误结论。

正确写法（本文件所有变异验证都用的这个）：

```bash
node test/xxx.mjs > /tmp/out.log 2>&1; echo "EXIT=$?"; tail -5 /tmp/out.log
```

### 4.2 只改 TS 不构建，用户看不到

见 §3.4。这一条和 4.1 是同一类错误：**验证的信号源不对**。
4.1 验证的是 `tail`，4.2 验证的是源码而不是产物。

### 4.3 `typecheck` 过了不等于构建过了

`tsc --noEmit` 只查类型，`vite build` 才会真的把模块打进去。
这一轮两个都跑了，但以后不能只跑前者就宣布"前端好了"。

## 6. 残留问题

1. **旧版面板（`ui/`）仍然看不到。** `/legacy/` 那个 3474 行的 `ui/app.js` 没接
   `/api/skips`。现在的默认入口是 `/console/`，所以影响面小；但只要有人用
   `/legacy/`，就还是看不到。**取舍**：旧面板已在退役路径上，不再加功能。

2. **跳过记录只在内存里，重启即清空。** `recentSkips()` 读的是 `RING_MAX=200`
   的环形缓冲，`data/skip-log.jsonl` 只是落盘副本（`MAX_LINES=240` 环形裁剪）。
   所以"昨天为什么没回"查不到。**取舍**：这是有意的（排障看的是"刚才"），
   但用户可能误以为是历史。

3. **`stats` 的时间窗口和 `items` 不完全等价。** `since` 只过滤
   `recentSkips(limit)` 之后的切片，若记录数超过 `limit`，`stats` 统计的是
   "过滤后仍在内存里的全部"，而 `items` 只是前 `limit` 条。测试里
   `limit=200`（等于 `RING_MAX`）时两者一致，`limit` 更小时会不一致。
   **影响**：只影响"明细少于统计"的观感，不影响结论。

4. **`spent` 是人工判断，不是机器推导。** 它写在标签表里，靠人想清楚"这个阶段
   到底有没有调模型"。加新 stage 时如果填错，面板就会误导。**缓解**：
   `test-skip-labels.mjs` 对 7 个"必然没花钱"和 7 个"必然花过钱"的阶段做了
   双向断言，填反会红；但中间地带（比如将来的新阶段）仍需人工判断。

5. **没有"点开一条看完整上下文"的能力。** 明细只显示 `detail` 的前 6 个键
   （`Object.entries(...).slice(0, 6)`），超出的看不到。`traceId` 是唯一的把手，
   但面板里没有"按 traceId 串起整条链"的入口。

6. **统计徽章只显示前 8 类**（`rows.slice(0, 8)`）。阶段多的时候后面几类看不见，
   而它们可能正是"花了钱"的那几类（排序是次数降序，不是 `spent` 优先）。
   **可能的改法**：先按 `spent` 分组再按次数排。这一轮没做，因为真实数据里
   同时出现的阶段很少超过 3 类。
