# 拟人对话内核 v2 —— 从六个参考包里学什么、加什么、不加什么

日期：2026-10-19
范围：`src/talk-session.js`、`src/tier.js`、`src/rhythm.js`、`src/memory-facts.js`、`src/persona-audit.js`
接线：`reply-gate.js` / `orchestrator.js` / `prompt.js` / `sender.js` / `config.js`

---

## 0. 一句话

QQagent 原来是「每轮无状态 + 全局一份上下文预算 + 模型自己决定接不接」。
这次补的是**跨轮的那一层**：谁在跟我聊（锚点）、这一轮该带多少历史（档位）、
开口该等多久（节奏）、这个人我长期记得什么（事实库）。

**奥卡姆剃刀**：只补"没有它就一定不像人"的东西。以下**故意不做**：

- 不搬《常用知识库》那 6.3MB 的梗/百科（检索质量不如现有 `search_meme` + 联网，纯增体积）；
- 不搬酒馆卡的面板（十维只做"体检"，不做卡库/导入/五色 UI）；
- 不搬 SQLite（现有 JSON/JSONL 足够，多一个驱动只多一处部署风险）；
- 不做"AI 精简记忆"（一次额外模型调用换来的收益，不如把提取阈值调好）。

## 2. 数据流（一次群聊唤醒）

```
消息进 store
   ↓
#gateAllowsWake
   ├─ reply-gate.decideWake()
   │    private → @/点名 → 引用我 → 关键词 → ★continuation → 概率(活跃期/冷场)
   │    返回 { wake, reason, kind, tier }
   └─ ★talk-session.talkWindowOf(chatKey)
        锚点是谁 / 还剩多少窗口 / 是不是该软收尾
   ↓（值得跑）
#runAgent
   ├─ tier = decision.tier            → prompt 的【过去状态】按档位收窄
   ├─ talkBefore                       → prompt 的【现在这段对话】
   ├─ speaker(QQ)                      → prompt 的【当前对话】+ 【你长期记得的…】
   ├─ sender.beginRun(tier, startedAt) → 首条消息的"总延迟预算"
   ├─ agent loop（工具调用照旧）
   └─ 收尾
        ├─ noteTalkReply()  只记账：发没发、是不是锚点、是不是第 12 轮
        ├─ sender.endRun()
        └─ #maybeExtractFacts() 后台：只喂"这个人的话 + 我的回复"
```

## 3. 五个新模块（各自的边界）

### 3.1 `talk-session.js` —— 只记账，不判定
状态：`{partnerId, partnerName, turns, startedAt, lastBotAt, lastTextAt}`，落盘
`data/talk-state.json`（原子写，6 小时陈年状态自动丢弃）。

四条规则（`noteTalkReply`）：

1. 软收尾 / 被图片表情收尾 → 结束；
2. `continuation` → 锚点 +1 轮；
3. `named/keyword/private`：第三人 → 只刷窗口不换锚点；锚点本人 → +1 轮；没锚点 → 成为新锚点；
4. 对锚点一个字都没发 → 结束。

⚠️ **判定不在这里**。窗口、@、关键词都在 `reply-gate`；这里只回答"现在有没有一段对话、和谁、第几轮"。
混在一起就是"一个 `lastPartnerId` 被清空就全断"的老毛病。

### 3.2 `tier.js` —— 档位只压不放宽
`direct`（私聊/@/点名/接着聊）→ 一个字都不改；
`keyword` → 历史字数 ×0.75；
`interject` → 条数 ×0.55、字数 ×0.55。

`contextLimitsOf` 用 `min()`：用户把 `pastStateLimit` 从 24 调到 8，插话档不会反而算成 13。

### 3.3 `rhythm.js` —— 首条算总延迟，条间算抖动
- 首条：`目标区间 − 已耗时`（direct 1.2–2.0s，continuation 0.9–1.5s，interject 1.8–2.8s）。
  模型慢 2 秒就不要再硬等 1.2 秒。
- 条间：`max(minGapMs, 抖动) + 字数 × perCharMs`，上限 15s。
- `send.pace.enabled=false` → 完全回落旧的 `minGapMs~maxGapMs`。

### 3.4 `memory-facts.js` —— 第三层记忆（按 QQ，不按群）
- 只记"一年后仍有用"：称呼/生日/城市/职业/约定/持久偏好/雷点/重大事件；
- 重复出现 = 权重 +0.3（上限 2.0），不是再存一条；
- 衰减：每天 −0.02（≈50 天掉 1.0），低于 0.3 清掉；`negative` 不清；
- 上限 60 条/人，超了先丢最弱（`rule/negative` 不参与丢弃）；
- 凭据一律拒写；
- 提取：一次 JSON 调用，最多 3 条，**只喂这个人的话**，解析失败返回空数组（不编造）；
- 提示词标题写死"关于当前说话者本人的事，不是别人的"。

### 3.5 `persona-audit.js` —— 十维体检，不给总分排名
十维 × `{0..1}`，每维带命中的**证据词**；缺口给"该问什么"。
总评 = 覆盖 40% + 平衡 30% + 边界 15% + 可信 15%（不是几何平均——少一维不该把整张卡判死）。

```
npm run persona:audit              # 体检 config.json 里的人设
npm run persona:audit xiaojingyu   # 体检内置人设
npm run persona:audit -- --json    # 给脚本/面板
```

## 4. 配置（全部可选，缺省即生效）

```jsonc
{
  "talk": { "enabled": true, "windowMs": 20000, "stickerTolerant": true },
  "send": { "pace": { "enabled": true, "minMs": 1000, "maxMs": 3000, "perCharMs": 20 } },
  "memoryFacts": { "enabled": true, "injectLimit": 8, "minIntervalMs": 1800000, "minNewMessages": 16 }
}
```

关掉任意一项 = 回到 v1 行为（不删数据、不改调用路径）：

- `talk.enabled=false` → 每句都走概率；
- `send.pace.enabled=false` → 旧的固定间隔；
- `memoryFacts.enabled=false` → 不注入、不提取（已存的文件留着）。

## 6. 已知限制（先写在这，别当 bug 报）

1. **事实提取要花钱**：一次约 300 输出 token，节流 30 分钟 / 16 条新消息。小群可能一天只跑几次。
2. **提取归属只认"这一轮最后说话的人"**：多人同时刷屏时，可能漏记别人；但不会把 A 的事记到 B 头上。
3. **十维评分是词面证据**，不懂语义："我不在乎"会被算成"在乎"。它是缺口清单，不是考试分数。
4. **`talk-state.json` 单文件**：几百个会话也就几十 KB；没有做分片。
5. **首条延迟按"运行开始"起算**，不含防抖窗口（`wakeDelayMs`）——那是另一层，没动。
