# 音频格式兼容：市面免费工具调研 + QQagent 已集成的解法

2026-10-21。起因是两句需求：「唱歌出问题了，修复一下」→「找一找市面上能把歌曲转成 QQagent 可用格式的免费软件，并尝试应用」。

结论先说：**不用再让群友自己装软件转换了**，QQagent 现在能自己处理四大平台的加密文件和冷门格式。
调研里最有价值的那个工具（Unlock Music）的算法已经搬进代码。

## 一、当天到底坏在哪（两个真 bug）

现象：11:51 群友又发了一次《侧脸》（25 MB，48 kHz 的 flac 套着 `.wav` 扩展名），
作业在 `progress: 5` 卡了 279 秒，报「任务超时（心跳停止）」。

两个 bug 叠在一起：

### bug 1：`audio_io.py` 里的 `file_id` 根本没导入

```
NameError: name 'file_id' is not defined   ← audio_io.py:184
```

`file_id` 住在 `stage_cache.py`（内容指纹，用来给解码缓存起名），`audio_io.normalize_input`
里直接裸调却忘了 import。后果很阴：**任何非 44.1 kHz 的源**（48k flac、96k 高解析）
一进 `normalize_input` 就抛异常，而 route_a 那边没有中间日志，表现为「解码阶段一动不动」。

修：`from stage_cache import file_id`，加 try/except 兜底（单独 import 本模块时也不炸）。

### bug 2：`librosa.resample` 比 soxr 慢两个数量级

```
soxr.resample(1秒 48k 立体声)            → 0.00 s
librosa.resample(同一个数组, 'soxr_hq')   → 22.57 s
librosa.resample(同一个数组, 'soxr_vhq')  → 33.1 s
```

一首 3 分半的歌从「毫秒级」变成「两小时」，route_a 就这么静默卡死了。

修：`_resample` 里绕开 librosa 的封装，直接 `soxr.resample(..., quality='VHQ')`
（soxr 本来就是 librosa 的依赖，VHQ 就是 librosa 里最贵的那一档，等价）。
librosa 只作为 soxr 不可用时的兜底。

**效果**：同一个文件 `normalize_input` 从「240 秒超时」变成 **1.6 秒**。

## 二、加密格式解密：KGM 从「只能解 3 分钟」升级到整曲

昨天用 unlock-music 老版（网页 JS 版）的算法，靠一张 4 MiB 的 `kgm.mask` 查表，
只覆盖前 64 MiB 密文 —— 81 MB 的歌只能解出 177 秒。

今天读了新版 `KgmWasm/kgm.hpp`，发现它**已经不用那张表了**，改成 table1/table2 位移递推：

```c
uint8_t getMask(size_t pos) {
    size_t offset = pos >> 4;
    uint8_t value = 0;
    while (offset >= 0x11) {
        value ^= table1[offset % 272];
        offset >>= 4;
        value ^= table2[offset % 272];
        offset >>= 4;
    }
    return MaskV2PreDef[pos % 272] ^ value;
}
```

没有表长上限，**整首歌都能解开**。实测 81 MB / 3:37 的 96 kHz 24 bit flac：
全曲解码零错误、时长 217.85 秒、耗时 1.9 秒（含一遍完整解码校验）。

顺手做的优化：`maskValue` 只依赖 `pos >> 4`，同一个 16 字节块内是常数，
主循环按块复用，少算 16 倍。

`data/kgm.mask` 那张 4 MB 表已经不需要了，代码里已删掉下载逻辑（少一个网络依赖）。

## 三、市面免费工具清单（实测可用性）

| 工具 | 免费 | 能干什么 | 在我们环境下的可用性 |
|---|---|---|---|
| **Unlock Music**（unlock-music.dev） | 开源 MIT | 15+ 加密格式解密：qmc 全系、ncm、kgm/vpr、kwm、xm、mg3d、x2m、joox | **算法已搬进 QQagent**；网页版 `demo.unlock-music.dev` 可直接用；源码可 `git clone https://gitcode.com/gh_mirrors/un/unlock-music.git`（GitHub 被 451 拦，gitcode 镜像通） |
| **ffmpeg** | 开源 | 万物转码：ape/wma/dsf/m4a/aac → wav/mp3，视频抽音轨 | **已内置**（`media-tools.resolveFfmpeg()`，在 GPT-SoVITS runtime 里），QQagent 的转码全走它 |
| **ncmdump** | 开源 | 网易云 .ncm 专用，C++/Go | GitHub 下载不了；但它就是 AES-128-ECB + RC4 keybox，**已用 Node 复刻进 `src/audio-decrypt.js`** |
| **FormatFactory 格式工厂** | 免费（有捆绑） | Windows 图形界面批量转码 | 只能转普通格式，**解不了加密文件**；安装包有捆绑，装的时候要留神 |
| **fre:ac** | 开源 | 音频转换（ape/flac/wma/aac） | 能用，但只是 ffmpeg 的图形外壳，QQagent 不需要 |
| **VLC** | 开源 | 播放 + 转码 | 能转普通格式，解不了加密 |
| **Audacity** | 开源 | 剪辑 + 导出 | 适合人工修，不适合自动化 |
| **在线转换网站**（各种 "音乐解锁" 在线版） | 免费 | 拖文件解密 | **不推荐**：文件要上传到别人服务器，隐私和版权都不干净 |

**版权提醒**：这些工具只应处理自己合法获得的文件（个人备份/自己设备上听）。
解密不等于获得授权，别拿去传播。

## 四、QQagent 现在能吃什么

`saveIncomingSong` 是统一入口，群友发什么都先过它：

| 输入 | 处理 |
|---|---|
| 酷狗 `.kgm` / `.kgma` / `.vpr`（含改名成 `.flac` 的） | 自动解密 → 完整 flac（无损、不重编码） |
| 网易云 `.ncm` | AES-128-ECB + RC4 keybox 解密 → 原始 flac/mp3，顺带读出歌名 |
| 酷我 `.kwm` | 32 字节 mask 循环异或 → 原始 mp3/flac |
| wav / mp3 / flac / m4a / ogg / aac | 直接入库 |
| ape / wma / 视频文件等 | ffmpeg 转 44.1k 立体声 wav 后入库 |
| QQ 音乐 qmc 系列（qmcflac/mflac/mgg） | **解不了**，需要客户端密钥；如实告诉群友换文件 |

扩展名一律不信：判断只认魔数（KGM 的 `7cd532eb…`、NCM 的 `CTENFDAM`、KWM 的 `yeelion-kuwo…`）。
