# 寻址：和群友说话时，她别以为在跟她说话

日期：2026-10-22

## 症状

「群里我和群友聊天，她会插进来，好像我是在跟她说话。」

不是"回复率太高"这种模糊问题，是**认错了说话对象**。

## 根因（三个叠在一起，缺一个都不会这么明显）

### 1. 「@ 了谁」从来没被结构化过

`store.appendIncoming` 的入参里有 `reply = null`，而入站侧**从没传过**它。
于是 `entry.reply` 永远是 null，后果有两个：

- `reply-gate` 里「引用我的话 → 唤醒」这条判据是**死代码**，引用信息只以
  `[引用 张三：原文]` 的形式混在文本里，没有任何人去读；
- 提示词里 `m.reply?.sender` 也永远是空 → `[引用 张三：…]` 前缀从不显示，
  模型看到的是一句没有上下文的话。

### 2. 提示词只认「@ 开头」

`prompt.js::triggerLabels` 第一句是：

```js
if (text.startsWith('@') || ...) labels.push('@我');
```

群里 `@张三 晚上吃啥` 也以 `@` 开头 → 标注成 **「@我」**。
模型拿到的证据是"这条在叫我"，于是理直气壮接了过去。
**这是最直接的成因。**

### 3. 没有「提到名字 ≠ 叫名字」的概念

只要文本里出现她的昵称就算被叫。于是
`@张三 你看小鱼多能说` 也会触发 `named` —— 那句话明明是在跟张三说。

## 方案：加一层「寻址判定」（`src/addressee.js`）

纯函数，不 import config、不碰磁盘、不联网。输入一条消息，输出一个结论：

```js
target: 'self' | 'other' | 'all' | 'none'
```

优先级是刻意定死的顺序（想改之前先想清楚）：

1. `@我` / 引用我的话 → **self**（明确叫它，最优先）
2. `@全体成员` → **all**（在叫所有人，它也算一个）
3. `@别人` / 引用别人的话 → **other**（明确在跟别人说）
4. 提到它的名字（没 @ 也没引用）→ **self**（叫名字本来就是叫它）
5. 都没有 → **none**（公屏闲聊，谁都可以在）

★ **第 3 条压过第 4 条是本模块存在的理由**：
"@张三 你看小鱼多能说" 是在跟张三说话，不是叫小鱼 —— 提到名字不等于叫名字。

输入分两路，结构化优先、文本兜底：

- 结构化（新消息）：`entry.atSelf` / `entry.atOthers[]` / `entry.reply{senderId,sender,self}`
- 文本（老存档）：扫 `@张三`、`@我`、`@全体成员`、`[引用 张三：…]`

昵称可能带空格（`AI 酱`），所以文本解析是**先用昵称整段匹配掉 `@它`，
剩下的 `@` 才是别人** —— 否则 "AI 酱" 会被空格切成 "AI"，自己的名字反被当成别人。

## 接线

### 入站（`app.js::ingestMessage`）

段里就有的东西，扫一遍不用联网：

- `at` 段 → `atSelf` / `atOthers`（名字留到 `segmentsToText` 之后再解析，
  那时 `resolveAtName` 缓存已热，不多打一次接口）
- `reply` 段 → `replyRefId` → 落库成 `reply{sender,senderId,text,self}`

顺带给 `resolveReply` 加了 message_id 级缓存 —— 同一条被引用的消息之前会被
`get_msg` 打两遍（渲染一遍、寻址一遍）。

### 唤醒闸门（`reply-gate.js`）

- 强触发只在**不是"对别人说"的条目**里找 → `@别人` 的消息再像也不算证据；
- `continuation` 追加条件：**最后那条不是对别人说的**。
  这就是"我转头和群友说话，她还一句句接下去"的那条路径 —— 她是锚点没错，但我已经换人聊了；
- 概率路径末尾乘寻址倍率，`to-others` 单独一个 skip reason
  （和"掷骰子没中"分开，事后能看出是降权生效还是运气）。

### 提示词（`prompt.js`）

触发块每条消息后面加寻址标注，规则 5.1a 说明它的含义：

```
小明(QQ:20001)：@张三 晚上吃啥（对张三说）
小明(QQ:20001)：@我 在吗（@我/提问）
小明(QQ:20001)：小鱼帮我看看这个（提到我）
张三(QQ:20002)：[引用 小明：晚上吃啥]火锅（对小明说）
张三(QQ:20002)：[引用 小鱼：嗯]对对对（引用我）
```

「（对张三说）」必须盖过「提到我」，否则模型照样会以为在叫它。

⚠️ **当前默认 `gate.dryRun: true`，闸门是"演练"的（一律唤醒、只标记 wouldSkip），
所以生产上真正拦住它的是这一层标注，不是闸门。**
等 `dryRun` 关掉，闸门那半边才会真正开始省钱。

### 省钱预判层（`wake-gate.js`）

极简清单里也给"对别人说"打标注，并写进规则：
「行末标了（对某某说）→ 直接判不接」。几百 token 的那次预判就能挡掉整轮。

### 旁听（`isSideTalk`）

最后两条来自**两个不同的人** = 那两个人在对谈，她是旁人 → 概率 ×0.35。
同一个人的连发不算（那是他在自己说，插一句不算抢话）。

这条是为了覆盖"没 @ 也没引用、纯自然的一问一答"那种情况。

## 配置（`gate.addressee`）

```js
addressee: {
  enabled: true,
  toOtherFactor: 0.08,   // 明着对别人说 → 概率乘这个
  sideTalkFactor: 0.35   // 两个群友在对谈 → 概率乘这个
}
```

都不是"禁止"，想彻底不接就写 `0`。`enabled: false` 整层停用（退回旧行为）。

旧配置没有这一块也没关系：`deepMerge` 会自动补默认值，已有字段不动。

## 副作用 / 要说在前面的话

**她会明显变安静**，尤其是在人多的群里：

- 明着对别人说 → 几乎不接（0.08 倍）
- 两个人在对谈 → 少接（0.35 倍）

如果觉得太闷，把 `sideTalkFactor` 往 1 调；觉得还在乱接，把 `toOtherFactor` 调到 0。

改了行为的还有一处：原来 `A问B答` 在 score 模式下会唤醒，现在不会了
（`test-ecosystem-borrows` 里那条用例已按新意图改写）。
