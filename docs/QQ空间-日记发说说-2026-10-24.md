# QQ 空间：把她的日记发成说说（2026-10-24）

## 一句话

日记照旧只写本地（`data/diary/<会话>/<日期>.md`），发到空间的是**另一份脱敏简版**，
走 NapCat 的扩展接口 `POST /send_qzone_msg`，默认**仅自己可见**。

## 为什么这么设计

| 决定 | 原因 |
| --- | --- |
| 走 NapCat，不自己拼 Cookie | QQ 空间 web 接口要 `g_tk` 签名，手搓 skey/p_skey 容易触发风控、掉登录态。NapCat 本来就握着登录态，失败了还回人话。 |
| 本地存全文、出去用简版 | 群友说过的话属隐私。本地档案要完整（给连续性用），发出去的那份不能带昵称/群号/真名。 |
| 默认 `ugc_right=64` | 1=所有人 4=好友 64=仅自己。日记里全是别人的对话，公开就是事故。 |
| 生成时多要一个 `public` 字段 | 不额外调模型、不多花钱：同一次 JSON 输出里多一个字段。只有真要发空间时才要求（`diary.publicSafe`）。 |
| 记账 `data/qzone-posts.json` | 一天一篇、不重复发；手滑点两次也不会刷屏。删了说说用 `forgetPost(tid)` 清账。 |
| 只发"最热闹的那一篇" | 早上好几个群都有日记，默认 `maxPerDay=1`，按当天消息量挑一个，别一早上刷满空间。 |

## 代码

- `src/qzone.js`：发布、脱敏（`redactForQzone`）、纯文本化（`stripMarkdown`）、截断（`clampText`）、账本。
- `src/diary.js`：`buildWritePrompt({publicSafe})`、`writeDiaryFor` 存 `<日期>.public.json`、`readPublicEntry`、`listDiaryChatKeys`。
- `src/orchestrator.js`：`#diaryTick` 写完后调 `#publishDiaries`（自动）；`publishDiaryNow` 供手动。
- `src/app.js`：`GET /api/qzone/status`、`POST /api/qzone/publish`；手机端白名单放行 `qzone.{enabled,autoPublishDiary,ugcRight}`。
- `ui-mobile/index.html`：「其他」分组里的开关 + 「日记发到 QQ 空间」面板（列表 + 单篇发送）。

## 配置（`data/config.json` 的 `qzone`）

```json
{
  "enabled": true,
  "autoPublishDiary": true,
  "ugcRight": 64,
  "maxPerDay": 1,
  "maxChars": 900,
  "includeTitle": true,
  "publicSafe": true
}
```

## 坑

- **`send_qzone_msg` 是 NapCat 扩展，不是 OneBot 标准**。老版本没有 → 404 → `onebot.js` 会把动作永久拉黑，
  报错文案是「当前协议端不支持」（`reason=unsupported`）。升级 NapCat 即可，别去改动作名。
- **成功但没回 tid = 结果不确定**（`reason=uncertain`）：可能已经发出去了，不能自动重发，要人去看一眼空间。
- **可见范围只认 1/4/64**：16/128 需要 `target_uins` 名单，这里不支持，传了会被退回 64。
- **说说只认纯文本**：模型偶尔留 `**粗体**`、`## 标题`，`stripMarkdown` 负责抹掉。
- **手机端下拉框只能给字符串**：`ugcRight` 在 `pickMobileConfig` 里强制转数字，否则配置里会出现 `"64"`，控制台数值比较全错位。
- **日记目录里的 key 不能瞎反解**：`group:123:xxx` → `group_123_xxx`，反解回来是错的。
  `listDiaryChatKeys` 只认 `<kind>_<纯数字id>`。

## 验证

```bash
node test/test-qzone.mjs     # 纯逻辑 + 幂等账本（14 项）
node test/test-diary.mjs     # 回归（18 项）
```

真实链路验证要连上协议端：手机端「其他 → 日记发到 QQ 空间」点一篇发，
或 `POST /api/qzone/publish {chatKey, date}`，成功返回 `tid`。
