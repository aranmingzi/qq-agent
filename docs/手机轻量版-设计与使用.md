# 手机轻量版（/m/）· 设计与使用

> 2026-10-20 首版。手机不是"移植一份 QQagent"，而是**遥控器**：算力、模型、QQ 会话全部留在电脑上，
> 手机只发 HTTP 请求读写配置。

---

## 1. 为什么不能移植

| 依赖 | 手机为什么跑不了 |
| --- | --- |
| SnowLuma / NapCat | 依赖 Windows 上的 QQ 客户端进程（NapCat 跑在 QQ.exe 里），Android/iOS 上没有等价载体 |
| RVC / DDPS-SVC / DiffSinger | 需要 CUDA + 数 GB 权重 + 几十 GB 依赖，4GB 显存刚够，手机 GPU 无对应运行时 |
| 点歌台 | 依赖 B 站 PC 端缓存目录与 ffmpeg 转码，属于"电脑上的文件整理" |
| 常驻性 | 手机后台会被系统杀，机器人会随手机锁屏掉线 |

所以手机端能做的、也只需要做的，是**读状态 + 改配置 + 暂停/重启**。
这恰好是"人不在电脑前"时唯一的真实需求。

## 2. 拓扑

```
手机（PWA /m/）
   │  HTTP + SSE，同源 cookie
   ▼
电脑：http://<内网IP>:3210
   ├─ src/app.js        HTTP API / SSE / 静态页
   ├─ SnowLuma+NapCat   QQ 登录与收发
   └─ RVC / DiffSinger  唱歌链路（GPU）
```

手机与电脑之间只走一条路。**没有云中转、没有账号体系**，令牌就是全部凭证。

### 地址怎么选

开启手机访问时接口会返回两组地址，界面默认只显示**内网**那一组：

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `privateAddresses` | `10.x` / `192.168.x` / `172.16-31.x` / CGNAT | 手机连同一 WiFi 用这个 |
| `publicAddresses` | 网卡上直接持有的公网 IP（典型来源：拨号网卡 / 宽带连接） | **不要用**，见下方警告 |

这个区分是必要的，不是洁癖：在单机 PPPoE 拨号的机器上（`宽带连接` 网卡直接持有公网 IP），
`os.networkInterfaces()` 里公网地址和 WiFi 地址是并列的，按枚举顺序很容易把公网 IP 排在前面当访问地址印给用户。
结果有两个：手机连同一 WiFi 用公网 IP 访问，多数家用路由器不支持 NAT 回环，**直接连不上**；
同时 `bindHost=0.0.0.0` 意味着如果路由器放行了 3210，控制台**从公网可达**。

所以：启动日志在检测到公网网卡地址时会单独打一行警告，`/m/` 界面也会把公网地址折叠成一句提醒。
外网访问请走 **Tailscale**（手机装客户端后直连 `http://<tailscale-ip>:3210/m/`，零公网暴露），
或者 Cloudflare Tunnel + Access。**不要做路由器端口映射。**

## 3. 三层安全模型

### 3.1 监听层：默认不开口

`server.bindHost` 默认 `127.0.0.1`。改成 `0.0.0.0` 才会对外监听。

`auditBindHost()` 在 `start()` 里做 fail-closed 检查：**非回环监听 + `server.token` 为空 → 强制退回 `127.0.0.1`**，
并在日志里打警告。理由：这个面板能改模型密钥、切 QQ 账号、看群名单，不能出现"同网段任何人打开就是管理员"的状态。

### 3.2 凭证层：三种来源，cookie 优先给手机

`authorize(req)` 按 `header > cookie > query` 取值，用 `crypto.timingSafeEqual` 定长比较：

| 来源 | 谁用 | 说明 |
| --- | --- | --- |
| `x-console-token` | PC 控制台、脚本、curl | 自定义 header |
| `qqagent_token` cookie | 手机浏览器 | `HttpOnly; SameSite=Lax; Path=/`，有效期 30 天 |
| `?token=` | 仅兼容旧调用 | **会进访问日志与 Referer**，手机端不用 |

**为什么必须要 cookie**：`/api/events` 是 SSE，浏览器 `EventSource` 无法设置自定义 header。
只支持 header 的话，手机端的实时状态就永远是 401。cookie 是同源自动携带的唯一选择。

`HttpOnly` 挡住 JS 读取；局域网多为 http，所以**不能加 `Secure`**（加了浏览器直接丢弃）。
`server.token` 也不下发给浏览器（`publicConfig` 里掩码），避免 XSS 顺手把门钥匙取走。

### 3.2.1 本机页面自动发凭证

设了令牌之后，`/console/`、`/m/` 这类 HTML 响应在**请求来自回环地址**时会顺带 `Set-Cookie`。

这不是放水，是补一个必踩的坑：**Electron 壳、系统浏览器、无痕窗口各有独立的 cookie 仓库**。
用户在 /m/ 里配好令牌后，回到 Electron 窗口打开 `/console/` 会发现每个接口都 401、界面空白，
而界面上没有任何提示告诉他"你没有凭证"。

本机就是这台电脑的主人（他本来就能直接读 `data/config.json`），给他发凭证不降低实质安全性；
手机走的是局域网 IP、不是回环地址，拿不到这个自动凭证，仍然必须登录。

### 3.3 权限层：手机拿不到全量写权限

PC 控制台的 `POST /api/config` 是整包 `deepMerge`，等于全权。手机端另开一个口子：

```
POST /api/mobile/config
  → pickMobileConfig(body)  // 默认拒绝，只放行 MOBILE_CONFIG_GROUPS 里的键
  → stripMaskedSecrets()    // 掩码值不会被写成真密钥
  → updateConfig()          // 与 PC 端共用同一个副作用
```

被丢弃的字段会在响应 `ignored` 里回报，前端提示"N 项不在手机端权限内被忽略"，而不是静默失败。

**故意不在白名单里**：`server`（令牌/监听地址）、`allow`/`deny`（白名单）、`providers`（含密钥目录）、
`snowluma`（QQ 登录）、`customPersonas`、`personaBindings`、`persona.masterQQ`。

### 3.4 开关层：只能在本机开门

`POST /api/mobile/enable` 校验 `req.socket.remoteAddress` 是回环地址才执行。
远程能改监听地址和令牌，等于"远程能给自己开门"，这一条必须卡死在本机。

## 4. 开启流程

```
PC 浏览器 http://127.0.0.1:3210/m/
  │  ① GET /api/auth/status        → { required:false }
  │  ② POST /api/mobile/enable     → 生成 24 字节 base64url 令牌
  │                                 写 server.bindHost='0.0.0.0' + server.token
  │                                 返回 { token, addresses:[http://IP:3210/m/] }
  │  ③ POST /api/auth/login {token} → Set-Cookie（重启后仍然有效，不用再输）
  │  ④ GET /api/mobile/qr?url=...   → SVG 二维码（仅本机、仅本机网卡地址）
  │  ⑤ POST /api/restart            → 重启后监听生效
  ▼
手机扫码 → /m/ → 自动带 cookie 进入
```

关闭走同一接口 `{enable:false}`：`bindHost` 回 `127.0.0.1` 并**清空令牌**。
清空是为了避免"我只想关手机访问，结果本机控制台突然开始要登录"这种困惑。

## 5. 页面结构

单文件 `ui-mobile/index.html`，内联 CSS/JS，无构建、无依赖、无 Service Worker
（控制台必须联网才有意义，缓存旧页面只会制造"改了没生效"的幽灵问题）。

`manifest.webmanifest` + `icon.svg` 让它能"添加到主屏幕"并以独立窗口运行。

### 5.1 字段声明驱动

```js
const GROUPS = [
  { id, title, desc, extra, items: [
      { path: "api.model", label: "主模型", type: "text", list: "models", help }
  ]}
]
```

`type` 支持 `text / number / range / select / switch / textarea`。
加一个设置项只改数组，不写渲染代码——与 `ui/schema.js` 的"骨架是数据"思路一致。

`test/test-mobile-console.mjs` 会解析这份声明，逐条比对后端白名单：
**声明了但白名单没有的字段，测试直接失败**，防止"改了没保存"的哑巴亏。

### 5.2 覆盖范围

| 分组 | 内容 |
| --- | --- |
| 模型 | 主模型、复杂模型、温度、输出上限、思考模式、看图 |
| 人设 | 名字、展示名、参与度、追加规则、人设文本（折叠）、模板切换 |
| 聊天行为 | 插话概率、防抖、连续对话、唤醒闸门、主动开话题、空白名单放行 |
| 语音与唱歌 | 语音开关、自动转写、音色、语气、干声、硬唱 |
| 其他 | 情绪、表情包、日记、长期记忆、每日预算 |

状态卡只读：QQ 连接、账号在线、SnowLuma 运行、当前模型、今日用量。
动作只有三个：暂停/恢复、重启、开启/关闭手机访问。

## 6. 已知边界

- **扫码登录放在手机会很别扭**：手机浏览器显示二维码，用户手上只有一个手机，扫不了自己的屏幕。
  所以手机端不提供 SnowLuma 扫码，需要登录时回电脑。
- **电脑休眠 = 手机全断**：这不是 bug。要长期可用，得在电源设置里关掉睡眠、并让 QQ Agent 常驻托盘
  （`server.closeToTray` 默认 `true`）。
- **公网访问**：不建议端口映射。要出门用就上 Tailscale（手机装客户端，直连电脑的 3210，零公网暴露）；
  Cloudflare Tunnel + Access 也行。面板权限太大，裸露公网等于把电脑交出去。
- **重启判定**：沿用 `startedAt` 变化，不是"能连上"——旧进程在重启窗口内也连得上。

## 7. 文件与测试

| 文件 | 作用 |
| --- | --- |
| `ui-mobile/index.html` | 全部界面与交互（含本机专属的「手机访问」卡片） |
| `ui-mobile/manifest.webmanifest` | PWA 清单（`start_url`/`scope` 都是 `/m/`） |
| `ui-mobile/icon.svg` | 图标 |
| `src/config.js` | `server.bindHost` 默认值与注释 |
| `src/app.js` | `MOBILE_DIR`、`auditBindHost`、`isLocalRequest`、`/api/auth/*`、`/api/mobile/*`、`/m/` 路由、`publicConfig` 掩码 `server.token` |
| `test/test-mobile-console.mjs` | 30 项：静态接线 + 隔离进程端到端 |

端到端测试的做法值得保留：临时 `QQ_AGENT_DATA_DIR` + `snowluma.wsUrl` 指向不存在的端口
（**绝不抢正式实例的 QQ 消息**），关闭 RVC/DDSP 自动拉起，测完还原 `snowluma/config/onebot11*.json`。

```bash
node test/test-mobile-console.mjs   # 30 项
```
