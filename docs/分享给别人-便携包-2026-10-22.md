# 把 QQagent 分享给别人（便携包方案）

> 2026-10-22 · 目标：别人电脑上**解压双击就能用**，不用装 Node、不用配环境、不会带走你的密钥和聊天记录。

## 产出物

| 文件 | 体积 | 作用 |
|---|---|---|
| `dist-portable/QQagent-便携版.zip` | 184 MB | 核心包：对话 / 记忆 / 表情 / 日记 / 点歌台 / TTS + NapCat + Electron |
| 唱歌环境（移动硬盘搬） | 47.8 GB | RVC 翻唱 / DiffSinger 唱旋律 / GPT-SoVITS / seed-vc + 曲库 + 背景乐 |

## 一、核心包：直接发给对方

对方拿到 zip 后五步：

1. **解压到纯英文路径**（`C:\QQagent`），不要放桌面 / OneDrive / 中文目录
2. **装 PC 版 QQ（NT 架构）并登录小号**，QQ 保持运行
3. 双击 **`启动 QQagent.bat`**（连不上 QQ 时改成右键 → 以管理员身份运行）
4. 控制台「设置」页：填 API 地址 + Key + 选模型；「白名单」勾选要它参与的群
5. 「存档」页发一条测试消息，群里收到即通

包内有 `首次使用必读.md`，内容就是这个流程的详细版（含常见问题）。

### 包内已强制清空的东西

打包脚本 `tools/make-portable.mjs` 每次都会做，并有自检兜底：

- 所有 `apiKey` / `token` / `secret`（API、语音、识图、访问令牌、NapCat WebUI token）
- 白名单里的群号、私聊 QQ 号、`persona.masterQQ`、`snowluma.accountQQ`
- `snowluma` 下的账号配置、登录缓存、日志、QQ 本地库残留
- 整个 `data/`：聊天记录、记忆、日记、表情库、群梗、会话存档**一个字节都不带**
- `src/` 里的 `.bak` 历史备份

保留的：**人设**（roleText / 自定义人设卡 / 参与度 / 行为参数 / 唱歌参数），这是你要带过去的"魂"。

### 自检输出示例

```
将剔除 7 个 QQ/群号、2 个密钥
✓ 未发现 QQ 号 / 群号 / 密钥残留
✓ snowluma 账号配置已清空
```

一旦扫到残留会直接报错退出（退出码 2），不会生成一个"看起来正常其实带密钥"的包。

## 二、唱歌环境：移动硬盘搬（47.8 GB）

压缩没意义——里面 90% 是 `.pth`/`.onnx` 模型权重，压一小时只省几 GB。直接拷更快更稳。

### 你这边（插上移动硬盘）

```bash
cd /d/QQagent
node tools/copy-ai-bundle.mjs --check                       # 先看清单和体积
node tools/copy-ai-bundle.mjs --to E:\QQagent-ai --verify   # 拷过去并校验
```

- robocopy 增量复制，**中断了重跑一次只补差量**
- 自动排除 `__pycache__` / `logs` / `tmp` / `*.log`
- 自动把 `C:\Program Files\Python312` 一起拷成 `runtime\py312` ←**这一步最容易漏，漏了 DiffSinger 在对方电脑上 100% 起不来**

### 对方那边

1. 先解压核心包成 `C:\QQagent`
2. 把移动硬盘里 `QQagent-ai` 下的 **10 个文件夹 + runtime** 整个拖进 `C:\QQagent`
3. 双击 `启动 QQagent.bat`

启动自检会打印：

```
[ok] diffsinger-env 已重新指向包内 Python：C:\QQagent\runtime\py312
```

这一步就是为什么换电脑后唱歌还能用——`diffsinger-env` 是 Python venv，`pyvenv.cfg` 里写死的是**创建那个 venv 的机器**的基础 Python 路径。自检每次启动都把它改回包内那份。

## 三、我改了什么

### 新增

| 文件 | 作用 |
|---|---|
| `tools/make-portable.mjs` | 生成核心包：白名单复制 + 配置脱敏 + NapCat 清场 + 泄露自检 + 可选压缩 |
| `tools/portable-setup.mjs` | 包内首次启动自检/自愈：修 `pyvenv.cfg`、建 data 骨架、体检 QQ/NapCat/Electron/API |
| `tools/copy-ai-bundle.mjs` | 唱歌环境搬运：清单、增量复制、关键文件校验 |
| `tools/portable/启动 QQagent.bat` | 启动器（先自检再起 Electron，不依赖系统 Node） |
| `tools/portable/首次使用必读.md` | 给对方的说明书 |

### 改动

`electron/main.js` 顶部加了一段：包根存在 `portable.flag` 时，把 Electron 的 `userData` 重定向到 `data/electron`。效果有两个——

- 数据、缓存全在包内，换电脑直接拷文件夹，删程序 = 删目录，无注册表残留
- 单实例锁跟着 userData 走，所以便携版和你本机的开发实例**可以同时开**，不会互相顶掉

不做这个改动的话，便携版会去抢 `%APPDATA%\QQ Agent` 的同名锁，同机测试时第二个实例会直接退出。

### 启动方式为什么不用 `npm start`

对方电脑没有 Node。启动器借用 Electron 自带的 Node 跑自检：

```bat
set "ELECTRON_RUN_AS_NODE=1"
"node_modules\electron\dist\electron.exe" "tools\portable-setup.mjs"
set "ELECTRON_RUN_AS_NODE="
start "" "node_modules\electron\dist\electron.exe" .
```

## 四、以后改了代码怎么重新打包

```bash
cd /d/QQagent
# 控制台改过的话先重建
cd console && MSYS_NO_PATHCONV=1 node ./node_modules/vite/bin/vite.js build --base=/console/ --outDir=../ui-console --emptyOutDir && cd ..

node tools/make-portable.mjs --zip
```

产物在 `dist-portable/QQagent-便携版.zip`。

改了唱歌环境（换音色模型、加曲库）才需要重拷唱歌包，改聊天逻辑不用。

## 五、已知边界（别踩）

- **对方必须有 PC 版 QQ**：NapCat 是注入本机 QQ 进程，不是模拟登录，绕不过去
- **对方必须有自己的 API Key**：包里没有你的，这是故意的
- **一个程序一个 QQ**：要两个号就复制两份文件夹
- **同机测试会串 NapCat**：便携版默认连 `127.0.0.1:3003`，本机主实例若在跑，两者会连同一个协议端（真实用户电脑不存在这问题）
- **唱歌环境对路径敏感**：纯英文路径最稳（`C:\QQagent`），中文路径 + OneDrive 同步目录偶发 torch/ffmpeg 加载失败
- **47.8 GB 是裸体积**：对方硬盘要留够，另外 RVC 第一次推理会占 2–4 GB 显存
