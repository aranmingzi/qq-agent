# 语音引擎全哑：CosyVoice 换模型后的两个兼容坑

修复日期：2026-10-20。涉及 `src/qwen-audio.js`、`test/feature-regression.mjs`。

## 1. 现象

群里让它发语音，什么都不出来，只有一条降级说明；手动跑一次合成，报：

```
语音合成失败：[cosyvoice:]Engine return error code: 418
```

`audio.model` 是 `cosyvoice-v3-flash`，`audio.voice` 是空。

## 2. 根因：两个坑叠在一起

### ① 音色不通用（418）

`resolveVoice()` 只写了两类模型的默认音色：qwen-audio 系列和 qwen3-tts 系列。
`cosyvoice-v3-flash` 落进兜底分支，拿到 `longanlingxin` —— 那是 **qwen-audio 的音色**，
CosyVoice 的音色表里根本没有。

报错里 `[cosyvoice:]` 冒号后面是空的，就是引擎没能解析出音色名的样子。

### ② instruction 是固定句式，不是自由描述（428）

音色换对之后，错误变成 428。逐个参数剥离后才定位到 `instruction`：

| 传的 instruction | 结果 |
|---|---|
| （不传） | ✓ 成功 |
| `你说话的情感是neutral。` | ✓ 成功 |
| `你说话的情感是 neutral。` | ✗ 428（多了半角空格） |
| `你说话的情感是neutral.` | ✗ 428（英文句号） |
| `你正在进行闲聊互动，你说话的情感是happy。` | ✗ 428（官方文档写的组合句式，这条 HTTP 路径不认） |
| `请用山东话表达。` | ✓ 成功 |
| `像真人在 QQ 上发语音聊天：口语化、自然…`（我们配的） | ✗ 428 |

结论：**CosyVoice 的 instruction 只接受单句、中文句号、句中不能有半角空格**。
中文句号和英文句号各错一次都会让整个请求失败。

而 `qwen-audio-3.0-tts-*` 吃自由描述（我们那句"像真人在QQ上发语音聊天…"在那边是加分项）。
所以这是**换模型带出来的**：配置从 qwen-audio 换成 cosyvoice，但音色和指令都还是老系列的语法。

## 3. 修法

`src/qwen-audio.js` 新增三个出口，都放在音色解析旁边：

```js
isCosyvoice(model)                  // cosyvoice-* 判定
resolveVoice(model, voice)         // 加 CosyVoice 分支：v3-flash→longanhuan，v3-plus→longanhuan_v3，v2→longxiaochun_v2
normalizeCosyvoiceInstruction(s)   // 自由描述 → 「你说话的情感是{emotion}。」
explainCosyvoiceError(msg, {...})  // 418/428 翻译成人话
```

`normalizeCosyvoiceInstruction` 的三条规则：

1. 已经是 `请用…表达。` → 原样放行（方言句式本身合法）
2. 已经是 `你说话的情感是xxx。` → 抽出情感值重建（**不修补原文**，空格标点错一个字符就 428，重建比修补可靠）
3. 自由描述 → 按关键词猜情感（`难过/失落`→sad、`生气`→angry、`俏皮/开心`→happy…），猜不到落 `happy`（与默认音色 longanhuan 的"欢脱元气女"一致）

**归一化必须留痕**：`buildTtsRequest` 返回 `notes`，`synthesizeSpeech` 用 `console.warn` 打一次
（`warnedNotes` 去重，不刷屏）。否则用户明明填了语气，听感却一成不变，会以为自己没配对。

错误码也补了归因，不再是光秃秃一句 `Engine return error code`：

```
…418｜音色「longanlingxin」不属于模型 cosyvoice-v3-flash：CosyVoice 与 qwen-audio 的音色互不通用，可用 longanhuan / longanyang…
…428｜instruction 句式不合法：只接受「你说话的情感是happy。」或「请用山东话表达。」这类单句，要求中文句号且句中不能有半角空格…
```

## 4. 验证

- 模块级：`synthesizeSpeech()` 用**原配置**（voice 空、instruction 自由长句）直接成功，
  182KB wav，`voice=longanhuan`，`instruction` 自动归一化为 `你说话的情感是happy。`
- 全链路：TTS → `convertVoice()`（RVC `robin`）→ 200KB wav，已换声
- 回归：`node test/feature-regression.mjs` 通过；新增 13 条断言（音色解析、三条归一化规则、
  请求体形状、418/428 的翻译）

## 5. 以后换 TTS 模型看这里

| 模型 | 端点 | 音色 | instruction |
|---|---|---|---|
| `qwen-audio-3.0-tts-plus/flash` | `/services/audio/tts/SpeechSynthesizer` | `longanlingxin` / `longanhuan_v3.6` | 自由描述可用 |
| `qwen3-tts-*` | `/services/aigc/multimodal-generation/generation` | `Cherry` | `instructions`（复数） |
| `cosyvoice-v3-flash` | 同上 `SpeechSynthesizer` | `longanhuan` / `longanyang` / `longanhuan_v3`… | **固定句式**，中文句号，无半角空格 |

换模型后先跑一次这个探针，比在群里试快：

```bash
node -e "import('file:///C:/QQagent/src/qwen-audio.js').then(async m => {
  const r = await m.synthesizeSpeech({ text: '测试一下语音引擎。' });
  console.log('OK', r.buffer.length, r.voice, r.model);
}).catch(e => console.log('FAIL', e.message))"
```

## 6. 这次没动的

- **`audio.voice` 仍留空**：`resolveVoice` 已经会按模型给正确默认值，写死反而在换模型时变成下一个坑。
- **`audio.instruction` 仍保留用户那句自由描述**：代码会归一化并提示一次。好处是将来切回
  qwen-audio 系列时，那句精心调的"语速放慢、傲娇俏皮"立刻又生效。
- **语速控制没做**：CosyVoice 有 `rate` 参数（0.5–2.0），但没实测过，不凭文档加参数。
- **GPT-SoVITS（9880）没启动不影响**：`audio.rvc.preferOverGsv=true`，
  `tools.js` 里 `useRvcOnly` 直接跳过 GSV 走 TTS→RVC。想用角色本音要把这个开关关掉并拉起 9880。
