## 二、拍人 / @人

**判据全在 `src/gesture.js`（纯函数、零依赖、28 项自检）**，工具和事件只负责接线。

### 入站：只认"冲我来的"
- 群里 `target_id` 缺失 → **不触发**（绝不把"谁拍的"当成"拍的谁"）；
- 私聊 `target_id` 缺失 → 按"拍我"处理（私聊只有两个人，这是场景决定的，不是猜）；
- 自己 `send_poke` 的回显 → 丢弃；
- 同一个 poke 重复推送 → 按 `会话|谁|拍谁|时间` 去重（30 秒窗口）；
- 拍的是别人 → **只留档当背景，不唤醒**（要改：`gesture.othersWake=true`）。
- 闸门同步加了 `poke` 理由（文本含「拍了拍你」必回）。

### 出站：按心情和现实分寸
| 约束 | 默认 |
|---|---|
| 一轮最多拍几次 | 1 |
| 同一会话两次拍 | ≥45 秒 |
| 同一个人两次拍 | ≥20 分钟 |
| 深夜 | 0–6 点不主动拍 |
| 心情 ≤35 | 不主动拍，但**被拍可以回拍**（回拍只留 8 秒手速） |

`send_poke` 现在支持 `targetUserId` 或 `targetName`（重名就不猜、直接失败），
`send_message` 支持 `atName`；@ 的规矩更严：私聊不 @（自动降级成普通消息并告知），
一轮最多 1 个。

## 三、语音回复发不出去

四个原因，逐个堵：

1. **ffmpeg 路径写死**在 `C:\Program Files (x86)\ACLOS\...`（别的机器上不存在）→ 转 16k 静默失败，
   44.1k 立体声被当语音条发出去。现在统一走 `media-tools.resolveFfmpeg()`（配置 → 项目自带 → PATH），
   失败会打日志而不是装没事。
2. **私聊也塞 `at` 段** → QQ 私聊没有 @ 语义，协议端让整条消息失败。现在 `#prefixSegments`
   按场景区分，私聊直接不带。
3. **路径投递失败没有退路** → `sendVoice` 现在失败自动换 `base64://` 再试一次
   （协议端不在本机/路径有中文/权限不足时，路径会失败而内联能过）。
4. **语音发不出去时话也丢了** → `send_voice` 改成：语音彻底失败就把这句话**用文字发出去**，
   并告诉模型"是形式失败不是内容失败，别再说'我用语音说'、也别重试"。

顺手修：`sendImage` 的 `replyToMessageId` 正则少了个反斜杠（`[1-9]d*`），
导致"回复某条消息时发图"只要 id 超过一位就报"必须是整数"。

## 四、网址解析不了

三个原因：

1. **编码**：中文站大量是 GBK/GB18030，以前一律按 UTF-8 读 → 乱码。现在
   响应头 charset → `<meta charset>` → UTF-8 严格 → gb18030 兜底。
2. **HTML 原文直接喂模型**：`<script>/<style>/<nav>/<footer>` 吃掉 2 万字配额，正文早被截断。
   现在 `htmlToText()` 提纯（保留段落换行、解码实体、丢隐藏元素），并返回标题。
3. **QQ 分享卡片只输出 `[卡片消息]`**：群友发的公众号/网页链接，地址就藏在 json 卡片的
   `jumpUrl`/`qqdocurl` 里，以前完全没取 → 模型手里没有 URL 可抓。
   现在 `cardLinkFromJson()` 抠出链接 + 标题，写成 `[卡片消息：标题 链接=https://…]`。

另外：补了 `gzip/deflate/br` 解压（不声明 accept-encoding 时，有些站会直接发 gzip 原文）；
URL 归一化支持缺协议头、Markdown 包裹、全角字符、句尾中文标点。

## 五、唱歌：优先语音，要完整才发文件

| 时长 | 交付 |
|---|---|
| ≤55 秒 | 一条语音条 |
| 55–165 秒 | 切成 2–3 条语音条连发（ffmpeg segment，带 20ms 淡入） |
| >165 秒 / 群友要"完整/文件/下载/高音质" | 音频文件 |

翻唱（`deliverCover`）也改成这套口径 —— 以前一律发文件，理由是 44.1k 立体声会被压坏，
但群友点歌要的是"立刻听到"，不是"下载一个 wav"。工具新增 `full` 参数。
