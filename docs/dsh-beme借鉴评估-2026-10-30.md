## 1. 直接可抄的（按收益排序）

### 1.1 版本链：`prev / head / origin` + OVERWRITE vs REBUILD 分流 ⭐ 命中 P0-4

它的 `addBlock()`（write.js:120-226）是"更正"的完整落地：

```
同 topic 找到旧块 → 算特征 Jaccard：
  ≥ 0.5（微改）→ OVERWRITE：原地 ver+1，prev 指旧版本，账本记 BLOCK_OVERWRITE（含 old/new 哈希）
  < 0.5（大改）→ REBUILD：开新坑（货位只增不复用），旧块内容不动、head 指向新块，
                账本记 BLOCK_REBUILD + edge("从旧说法变成新说法")
找不到旧块     → WRITE 全新坑
```

关键设计：**块库只是账本的视图，改写永远先记日志**（"先写日志再写库"是它的 A1 铁律）。
我们的 P0-4 计划（`supersedes: oldId` + 旧条打标不删）与它同构，但它多给两样可直接抄的：

- `content_hash` 字段：幂等判重从"文本归一化相等"升级为"内容没变才跳过"。
  它实测吃过反例：**只看 source_id 有没有同步过就跳过 → 记忆条目被整理后（id 不变、内容变了）
  永远进不了库，"22 小时零新增"**。我们的 `rememberFact` 用 `normalizeKey` 精确匹配去重，
  同一类bug的反面：同义改写撞不上、冲突说法并存 —— 加 hash + 冲突检测正好一起解决。
- `origin / origin_at`（溯源到这件事的第一次出现）：我们的"一次观察不算数"candidate
  转正后，可以用同一字段记"这事最早什么时候出现的"，问答时"这事是 X 天前的事"有据可说。

### 1.2 提取提示词的三条规则 ⭐ 命中 P0-2（第 2 步实施）

它的 `segmentPrompt()`（ai.mjs:37-58）已经把我们要写的禁令写出来了，且带实测理由：

- **"一块只写一件事。多人刷屏按'谁说了什么、她回了什么'拆开，别整段塞成一块"** —— 防串人的提取侧版本；
- **"纯表情、纯图片占位、纯灌水、别人的隐私八卦没有信息量 → 不要输出这一条"** —— 我们的弱句过滤；
- **"保留原话的口气和情绪，不要改写成书面语，不要替说话人美化"** —— 防"总结走形"
  （对外版："顺比错难查"的成因之一就是提取时美化）；
- **"同一人的不同叫法（本名/群名片/外号）不要当成两个人"** —— 我们的 matchMember 已在召回侧挡，
  提取侧也该有一句。

第 2 步改 `buildExtractionPrompt` 时直接把这四句化进去。

### 1.3 查询侧泛词过滤 + 小样本保护（read.js:108-117）

我们 `fact-recall.js` 的文档频率过滤（`maxDocRatio=0.8`）管的是**记忆侧**（剔除昵称）；
它补了另一半 —— **查询侧**：

```
df/N > 0.15 的词不算主题，是背景词，不计入查询特征；
但 df < 10（小样本）不杀 —— 块总数少时 df/N 天然偏大，会误杀正常词。
```

实测反例（注释原文）：问"光发表情什么意思"抽到"表情"→ 命中 69/347 块 → 注入一整段表情包记忆
→ **她跟着只发表情**。我们的 facts 只有一句话长、命中本来就稀，这个风险小；
但 past-summary（几百字条目）和未来的事件卡会踩 —— 抄判据（0.15 + 小样本下限）不抄参数。

### 1.4 检索四态出口：分不清就问，缺就明说（read.js:226-274）

`retrieve()` 返回四种状态而不是一坨内容：

| 状态 | 触发 | 注入的话术 |
|---|---|---|
| `ask_ambiguous` | 多条并列且没有一块命中全部特征（topF2<0.9） | "这几件是对得上的不同的事，你分不清问的是哪件，先别硬说，问了再答" |
| `assert_partial` | 槽位（几点/多少钱/哪里）没填上 | "你记得这些，但『时间』这项没记到，说的时候别编，缺就问主人" |
| `assert_full` | 全命中 | 正常注入 |
| `ask_empty` | 空库/特征抽空 | 不注入 |

这正是方案 R5 的"多个事件都相似而无法确定时，保留歧义或简短确认"的代码化，
而且它点破了一个我们的隐性缺口：**我们的召回只决定"注入哪几条"，从不告诉模型"没记到什么"**。
模型拿到 8 条事实里没有时间信息时，默认行为是编一个。低成本低改法：
`formatFactsForPrompt` 在 query 命中但无相关事实时，注入一句"记忆里没有关于 X 的记录，别编，缺就问"。

### 1.5 注入文案：直接陈述，不讲元话术（plugin/index.mjs:246-260）

```
'你知道这些事（都是你自己经历过、记下来的，不是别人告诉你的；聊到就自然用，别把旧事当新事说，也别提「记忆」这个词）'
```

它特意弃用了"你想起这些……"的包装 —— 两层括号叠起来模型会读乱，且元话术让模型把记忆
当"用户递来的资料"而不是"自己的记忆"。我们的 facts 段标题是"【你和他的长期记忆】"，
方向一致，可以借它一句"别把旧事当新事说"。

### 1.6 隐私护栏：查询意图 × 内容敏感 的交叉判断（read.js:245-257）

```
查询像"能不能说/告诉别人/群里"（PRIV_ASK） 且 命中内容含地址/电话/住址（PRIV_HIT）
→ 不注入原文，注入："这里有主人的隐私。规矩是：只给主人自己用，任何人问任何群都不复述…"
```

我们有 `factVisibleIn`（范围隔离）和 `CRED_RE`（凭据不落盘），但没有这一层：
**模型在群里被问"他家住哪"时，召回正常命中私聊范围的事实，注入后靠模型自觉**。
护栏做成"命中即换成规矩文案"比"指望模型看到后自己忍住"可靠。小改：注入前过一遍 PRIV_HIT。

## 2. 印证我们的选择（不用动，但它给了失败案例佐证）

| 我们的做法 | beme 的佐证 |
|---|---|
| append-only 归档 + 视图层可重建 | 它的 A1 铁律"先写日志再写库，日志绝不整文件重写"；blocks.json 标注"可重建" |
| 概率召回防自锁（加权抽样） | 它用"并列随机 + 查询哈希种子"——同一个动机（确定性 top-N 会复读），两种实现；我们的种子在 rng，它的种子可复现可调试，两种都成立 |
| 文档频率剔昵称（maxDocRatio 0.8） | 它的 `pruneVocab`（df>0.45 剔除）+ 注释"泛词是背景词不是主题"——同一条数学，两边各管一头 |
| 墓碑/休眠（昨天刚做） | 它没做失效语义（只有覆盖），恰是我们领先的地方；它的账本让"旧版本永在"，与我们"记录本体保留"同宗 |
| 坏文件隔离（json-store） | 它 `readJson` 静默 fallback —— 我们五条吸收 #1 之前的老毛病，反例再+1 |
| 不用向量库 | 它 README："精确查找不是模糊相似……它知道自己捞的是什么，也知道自己没捞到什么"——同立场，且词表天花板（71 词答不出"我叫什么"）印证我们"先把排序做对，量级到了再升级" |

它的 `topicOf` 正则拼主题键踩的坑（拼出「主人\|能力\|_」垃圾键 → **不同的事撞同一个 topic 互相覆盖，实测一个坑被覆盖 15 次**）
是我们 P0-4 文档里"冲突不保存、静默选顺口的一版"的活体案例 —— 它的修法（topic 优先用 source_id 派生稳定键）
印证我们"更正必须走显式 supersedes，不走启发式合并"的判断。

## 3. 明确不抄的

| 不抄 | 理由 |
|---|---|
| `SEED_VOCAB` / `GATE_BY_FEATURE` / `PRED` 硬编码词表与门类 | 全是作者自己语料（奶茶/象棋/分析化学）的人肉清单，三个月 71 个词就断供；我们的 tokenize 免维护 |
| `SLOTS` 槽位正则（几点/多少钱/什么型号） | 领域特化（它的语料是装机/奶茶外卖）；但**四态出口的框架**值得抄（1.4） |
| `sameEventWithAI`（让模型判两条是否同一件事） | 方向对但每对一次调用；我们按人分组 + 归一化匹配 + 未来的 hash 已够当前量级，等事实库上千再考虑 |
| 插件外壳的宿主适配层 | 它是 DSH cordis 插件，我们是自宿主；但它两条启动教训（插件入口名写错进安全模式、defineTool 必须带 output schema）与我们 plugin-host 的 capabilityState 思路互证 |
| `contextFor` 自动 pre-step 注入 | 它每轮只在 step 1 插一次、捞不到不插 —— 我们已有 context-budget 分槽体系，不需要第二套注入通道 |

## 4. 落到实施顺序上

- **第 2 步（提取禁令）**：1.2 的四条规则原文化进 `buildExtractionPrompt`；
- **第 4 步（supersedes 更正链）**：按 1.1 的 OVERWRITE/REBUILD 分流设计，加 `content_hash` 与 `origin/origin_at`；
- **新增小项（可随第 2 步顺手做）**：1.4 的"没记到就说没记到"注入句 + 1.6 的隐私护栏；
- **挂账不动**：查询侧泛词过滤（等事件卡/长条目检索上线时一起）。

## 5. 一句话

**dsh-beme 是"我们记忆架构的极简镜像"：同一条 append-only + 特征检索的路，走了 300 行就撞上的三个坑
（topic 互覆、幂等漏记、查询泛词），每一个都精确预言了我们 P0 清单里的位置。抄教训和两个机制，不抄词表。**

## 6. 实施落账（2026-10-30 凌晨，四样按性价比全部完成）

改动文件：`src/memory-facts.js`（全部四样）、`test/test-memory-beme.mjs`（新增 17 项）、
`test/test-memory-scope.mjs`（⑱ 占位数据改两字词，给弱句闸门让路）。

### ② 提取禁令（四条规则 + 解析层闸门）

- `buildExtractionPrompt` 新增四条：一条只写一件事（多人插话只看本人）/ 玩笑反讽气话一律不提取
  （宁可少记不可误当）/ 用他自己的措辞不改写不美化不补因果 / 同一人不同叫法不当两个人。
- 新增 `isWeakUtterance()` 纯函数 + 解析层弱句闸门：剥主语和引导词后，纯标点、单字、
  纯应答复读（嗯嗯/哈哈/说好）整条丢弃。"说好/说行"不算承诺——真承诺写成"答应XX"。
- 提示词是引导，闸门是保证：模型不一定听话。

### ③ 没记到就说没记到（四态出口的两档）

- **空档案档**：有 query + query 像提问（`QUESTION_RE`）+ 有档案但零命中 → 注入
  "目前没有与这句话相关的记录——别顺着编，不知道就直说"。
- **偏题档**：有命中行但 `queryHitAny` 单字粒度零沾边 → 注入"你问的 X 不在你记的这些事里——
  别拿不相关的旧事顶"。
- 粒度刻意放宽到单字：漏放的代价只是少一句提示（安全），误判的代价是真记得却被说"没记到"（伤人）。
- 陌生人和闲聊不触发（不每轮背定位句）。

### ④ 隐私护栏

- `PRIV_ASK_RE`（打听式查询）× `PRIV_HIT_RE`（住址/电话/课表等敏感内容）双命中 →
  整段换成规矩句，原文一个字不进上下文。普通查询照常注入（自己人正常问不拦）。
- 方向保守：误伤只少提一句，漏掉是私事上桌。

### ① 版本链（取 beme 的 REBUILD 腿，弃 OVERWRITE 腿）

- 新事实写入前过 `findConflict()` 双通道：
  - **复述通道**：去主语后 2-gram Jaccard ≥ 0.62 且**数字段相同**（"第1件事"≠"第11件事"，
    日期同理——实测回归抓出连环误替代）→ 判复述；
  - **更正通道**：带 cue 词（搬到/改成/不再/其实/后来…）且同主语 → 替代最相似条。
  - 判不出 → 并存（保守方向）。
- 命中冲突：新条带 `supersedes` + 继承 `origin/originAt` 血统；旧条打 `supersededAt/supersededBy`
  **不删**（它当年真过）。
- 被替代条四路退场：不召回、不衰减、不占容量、被重提时强化**转投替代者**（归档重读防线）。
- 所有新条带 `content_hash`（FNV-1a），load() 读回全部新字段（否则重启复活）。
- 明确不做 beme 的原地 ver+1：与我们"旧记录不改写"纪律冲突，改写一律走"新条+旧条打标"。

### 回归中抓出的三个误伤与修法（都是真教训）

| 误伤 | 症状 | 修法 |
|---|---|---|
| 同主语同构句连环替代 | "小明第0件事/第1件事…" 批量写入时 10 条被连环替代 | 复述门槛 0.5→0.62 |
| "第1件事" vs "第11件事" | 数字子串关系导致 0.83 高重合 | 数字段不同 → 绝不复述 |
| "张三a" 占位数据 | 单字后缀被弱句闸门丢弃（闸门行为正确） | 测试占位改两字词 |

**验证**：`test-memory-beme` 17 项新增全绿；107 个测试文件全量回归通过。
